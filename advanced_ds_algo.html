0 · The big picture

OpenLore never stores code as text. A source file enters as bytes and immediately becomes a parse tree, which is then reduced to a handful of purpose-built structures. Every "conclusion" the tool serves — which tests reach this change, what breaks if I delete X, where is auth handled — is a query against one of these structures, not a re-parse.

bounded scan + shards"] WALK --> TS["tree-sitter parse
one grammar per language"] TS --> EXT["extractors
functions · calls · imports · routes · schema · middleware"] EXT --> NODES["FunctionNode[ ] + CallEdge[ ] + DependencyEdge[ ]"] NODES --> PASS["build passes 1-6
fanIn/Out · communities · cyclomatic"] PASS --> ART[(".openlore/analysis
artifacts")] ART --> CSR["traversal-index
CSR + Tarjan SCC"] ART --> CFG["CFG / def-use

The unifying idea: the graph is the source of truth; everything else is an index over it. Text lines, embeddings, hashes — all are servants of graph queries.

2 · Graph structures (the spine)

2.1 · CSR adjacency CORE

condensation.ts:17 · 481–592

Compressed Sparse Row. The whole call graph is flattened into three typed arrays instead of a Map<string, Set<string>>. Strings are interned to dense integers once; after that every traversal runs on Int32Array with no allocation and no hashing.

nodeIds: string[ ] — dense id → string id (position is the dense id)
indexById: Map<string,number> — string id → dense id (the only Map on the hot path)
Csr.offsets: Int32Array[n+1] — offsets[v]..offsets[v+1] slices that node's edges
Csr.targets: Int32Array[m] — destination dense ids, contiguous
Csr.flags: Uint8Array[m] — one byte per edge slot: kind/confidence/eligibility bits
flowchart LR subgraph LOG["Logical graph"] A["entry"] --> B["loadUser"] A --> C["saveReceipt"] B --> D["logger.warn"] C --> E["DB.save"] end LOG -->|"intern ids, flatten"| ROW["CSR arrays (forward)"] ROW --> O["offsets = [0,2,3,4,4,4]"] ROW --> T["targets = [1,2,3,4]"] ROW --> FL["flags = [ _ , _ , _ , _ ]"]

2saveReceipt3..4[4]DB.save
3logger.warn4..4[ ]—
4DB.save4..4[ ]—
flowchart TD I["string id e.g. 'src/pay.ts::charge'"] --> M["indexById.get() → v : number"] M --> S["Csr.offsets[v] → Csr.offsets[v+1]"] S --> K{"for each slot k

Forward vs. backward, one structure

A second CSR (backward) stores reversed edges, so "who calls this" is as cheap as "what does this call." Blast radius walks backward; downstream impact walks forward.

flowchart LR subgraph FWD["forward CSR"] direction LR fA["caller"] --> fB["callee"] end subgraph BWD["backward CSR"] direction LR bB["callee"] --> bA["caller"] end FWD -.->|"same edges, reversed"| BWD
The flag byte — filters without rebuilding

Each edge slot carries bit flags so a filtered traversal (e.g. "direct resolved edges only") reads the flag instead of rebuilding an adjacency. The keep rule (condensation.ts:517): 

forward :  (flags & (filter.directResolvedOnly ? FLAG_FWD_ELIGIBLE_DIRECT : FLAG_FWD_ELIGIBLE_ALL)) !== 0
backward:  !(filter.directResolvedOnly && (flags & FLAG_SYNTHESIZED) !== 0)
flowchart TD SLOT["one CSR edge slot"] --> B0["bit0: FLAG_SYNTHESIZED"] SLOT --> B1["bit1: FLAG_FWD_ELIGIBLE_ALL"] SLOT --> B2["bit2: FLAG_FWD_ELIGIBLE_DIRECT"] B1 --> Q{"which filter?"} B2 --> Q B0 --> Q Q -->|default| USE["edge is reachable"] Q -->|directResolvedOnly| USE2["edge reachable only if eligible/direct"]
BFS on the arrays
const visited = new Uint8Array(nodeCount)   // doubles as the dedup set
const queue   = new Int32Array(nodeCount)  // head-index ring, O(1) dequeue (never shift())
let head = 0, tail = 0
for (const s of seedIdx) { visited[s] = 1; queue[tail++] = s }
while (head < tail) {
  const v = queue[head++]
  for (let k = offsets[v]; k < offsets[v+1]; k++) {
    if (!keep(flags[k], filter, dir)) continue
    const w = targets[k]
    if (!visited[w]) { visited[w] = 1; queue[tail++] = w }
  }
}
The old code used Array.prototype.shift(), which is O(n) per pop — a traversal was O(n²). The head index makes dequeue O(1). The comment in the source calls this out explicitly (condensation.ts:9).

2.2 · Tarjan SCC + condensation DAG CORE

condensation.ts:28 · refactor-analyzer.ts:183 · plan-parallel-work.ts:494

Cycles are collapsed first so reachability becomes a single linear sweep. Tarjan finds strongly connected components; each component becomes one super-node; the result is a DAG in topological order.

flowchart TD START["push root, index=0"] --> LOOP{"stack not empty?"} LOOP -->|yes| VISIT["set index/lowlink
push frame"] VISIT --> EDGE{"more edges?"} EDGE -->|"unvisited w"| RECUR["push w (iterative frame)"] EDGE -->|"w on stack"| LOW["lowlink[v] = min(lowlink[v], index[w])"] EDGE -->|done| CLOSE{"lowlink[v] == index[v]?"} CLOSE -->|yes| POP["pop until v → one SCC
(completion order)"] CLOSE -->|no| BACK["return, update parent lowlink"] POP --> LOOP BACK --> LOOP LOOP -->|no| DONE["components numbered in
reverse-topological order"]
Iterative, not recursive. A recursive Tarjan blows the JS call stack on a deep chain. The implementation uses an explicit frame stack so a 100k-deep dependency chain analyzes fine (guarded by condensation.test.ts:568).
flowchart LR subgraph CY["call graph with a cycle"] A["A"] --> B["B"] B --> C["C"] C --> A C --> D["D"] D --> E["E"] end CY -->|"Tarjan"| CON subgraph CON["condensation DAG"] S1["SCC{A,B,C}"] --> S2["SCC{D}"] S2 --> S3["SCC{E}"] end

3.2 · Personalized PageRank (query-seeded) CORE

personalized-pagerank.ts:1

Text book random-walk-with-restart, but the restart distribution is uniform over the task's matched symbols — not the whole graph. "Of the functions connected to this task, which are most relevant?" answered as a probability distribution over a bounded neighbourhood.

flowchart LR subgraph WALK["random walk with restart"] SEED["seed set
matched symbols"] -->|"restart prob (1−d)"| SEED SEED -->|"d · step to out-neighbour"| N1["neighbour"] N1 -->|"d · step"| N2["neighbour"] N1 -->|"restart"| SEED end
Why PPR over shortest-path distance? Distance ranks by the single cheapest path; PPR ranks by how many ways, and how densely, a node connects to the seeds — a node reachable by many independent paths outranks one reachable by a single long path (personalized-pagerank.ts:10). 
type WeightedAdjacency = Map<string, Array<{ to: string; cost: number }>>
// deterministic: nodes iterated in fixed sorted-id order → bit-identical floats across runs
// returns: Map<nodeId, relevanceProbability>  (sums to ~1 over universe)

3.4 · Brandes betweenness centrality CORE

dependency-graph.ts:600

Finds the files that sit on the most shortest paths between all pairs — the "bridges" of the codebase. This is Brandes' algorithm: one BFS per source, counting shortest paths, then back-propagating dependency scores.

flowchart TD SRC["for each source s"] --> BFS["BFS: distance[ ], sigma[ ] (path counts), predecessors[ ]"] BFS --> BACK["back-propagation (reverse BFS order):
delta[v] += (sigma[v]/sigma[w])·(1+delta[w])"] BACK --> ACC["betweenness[w] += delta[w] (w ≠ s)"] ACC --> RST["reset only touched nodes"] RST --> SRC ACC --> NORM["normalize by max betweenness"] 
// queue = array + head index  (O(1) dequeue, not shift())
for (const w of neighbors(v)) {
  if (distance[w] < 0) { queue.push(w); distance[w] = distance[v] + 1 }
  if (distance[w] === distance[v] + 1) { sigma[w] += sigma[v]; predecessors[w].push(v) }
}
// then pop the stack, accumulate delta, credit betweenness

4.1 · BM25 inverted index CORE

The first-class default: a keyword index that works with no embeddings, no network. Each function becomes a document over five fields; the query is scored with BM25 and every hit carries match evidence (which field, which terms, which tier).

Identifier-aware tokenizer (v2)

flowchart LR IN["getUserById"] --> SPLIT["split on [^A-Za-z0-9]+"] SPLIT --> LOW["lowercase compound: 'getuserbyid'"] SPLIT --> CMP["splitCompound: camelCase / PascalCase"] CMP --> PARTS["get · user · by · id"] LOW --> OUT["tokens: [getuserbyid, get, user, by, id]"] PARTS --> OUT 
splitCompound("getUserById")  // keep the compound AND its parts
  .replace(/([a-z0-9])([A-Z])/g, '$1 $2')   // getUserById → get User By Id
  .replace(/([A-Z])([A-Z][a-z])/g, '$1 $2') // HTTPServer  → HTTP Server
The acronym rule captures one capital, not ([A-Z]+). The old greedy form was quadratic: 200 KB of A took 129 s to tokenize. Byte-identical output, so the persisted index did not need rebuilding (bm25-tokenizer.ts:12).

4.2 · Vector index (LanceDB ANN)

vector-index.ts:1 · spec-vector-index.ts

Optional semantic layer. Each function's document is embedded and stored in a LanceDB table named functions; ANN search returns nearest neighbours. BM25 remains the fallback when no embedder is configured.

flowchart LR REC["FunctionRecord"] --> EMB["embed(document)"] EMB --> VEC["float vector"] VEC --> TBL[("LanceDB table 'functions'")] Q["query text"] --> QE["embed(query)"] QE --> ANN["ANN search over LanceDB"] TBL --> ANN ANN --> RES["ranked neighbours + vector match evidence (tier 2/3)"]
The index is versioned and append-only: every incremental update is a delete + add that leaves the previous version on disk. A compaction counter reclaims the garbage (see §8).

5 · Symbol resolution

"Trie" that is not a trie CORE

function-registry-trie.ts:12

Misnomer warning. FunctionRegistryTrie has no prefix tree. It is three hash maps giving O(1) lookup by three keys.
flowchart TD N["FunctionNode"] --> M1["byId: Map<id, node>"] N --> M2["byName: Map<'process', node[ ]>"] N --> M3["byQualified: Map<'Handler.handle', node[ ]>"] M1 --> L1["findById(id) → node | undefined"] M2 --> L2["findBySimpleName(name) → node[ ] (sorted for deterministic tiebreak)"] M3 --> L3["findByQualifiedName(cls, method) → node[ ]"]

6 · Hashing & fingerprints

6.1 · Normalized AST content hash CORE

symbol-content-hash.ts

A symbol's hash is taken over its parse tree, never the raw bytes. The walk emits a pre-order stream of node types, leaf token texts, and open/close markers. Comments are dropped, whitespace never enters the stream — so a re-indent or a comment rewrite hashes identically, but moving a statement changes the nesting and therefore the hash.

flowchart LR subgraph TREE["parse tree of charge()"] F["function_declaration"] --> I["identifier"] F --> B["statement_block"] B --> S["..."] end TREE --> WALK["pre-order walk"] WALK --> STREAM["(' function_declaration
L identifier charge
L statement_block
... ) function_declaration"] STREAM --> H["sha256 → first 16 hex"]
flowchart TD FILE["one file"] --> SPANS["per-symbol spans"] FILE --> RES["residual: everything no span contains
(imports, module-level code, class fields)"] FILE --> LAY["layout: run structure
T:n residual · S:id span · I:hash import"] SPANS --> H1["symbol hashes"] RES --> H2["residual hash"] LAY --> COMP{"compare two revisions"} H1 --> COMP H2 --> COMP COMP -->|"adding a function"| ADD["new layout entry; residual unchanged"] COMP -->|"moving main() across a def"| MOVE["layout changes → real difference detected"]

Imports are hashed individually, with a binds flag. A purely ADDED import (a new name nobody used) cannot change what existing symbols do, so hashing it apart keeps an "add import + edit function" diff symbol-exact. A removed/rewritten import, or a wildcard (import *, using namespace), rebinds names → treated as a module-level change.

flowchart LR IMP["top-level import"] --> OWN["own sha256"] OWN --> N["names: identifier texts bound"] OWN --> BF{"binds?"} BF -->|"yes (named)"| ADDITIVE["purely-additive eligible"] BF -->|"wildcard / blank / side-effect"| MOD["module-level change"]

6.2 · Graph digest (invalidation key)

condensation.ts:71

flowchart TD CG["SerializedCallGraph"] --> NODES["hash node id set (cg.nodes order)"] CG --> EDGES["hash each edge triple
(callerId, calleeId, synthesized)"] NODES --> SHA["sha256 → digest"] EDGES --> SHA SHA --> STAMP["stamped into llm-context.json AND the persisted structure"] STAMP --> READ["reader compares: same digest → reuse; different → rebuild"]
Signatures, phases and any non-structural field are excluded, so an edit that touches only those cannot invalidate the structure. The reader gets the key for free from JSON it already parsed — no hashing of a multi-MB artifact on the read path.

export function charge(userId: string, cart: Cart): Receipt {

  const total = cart.items.reduce((s, i) => s + i.price, 0);

The one-sentence summary. OpenLore is a graph-algorithms engine — CSR + iterative Tarjan + fixed-point ranking + BM25/ANN retrieval — wrapped in a strict determinism and disclosure discipline; the fancy containers it avoids are avoided because the graph structures already answer the questions better, and every future addition is admitted only behind an equivalence contract and a measured reason.
